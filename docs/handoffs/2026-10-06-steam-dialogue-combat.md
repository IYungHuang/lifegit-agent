# Steam 版對話卡牌戰鬥階段性交接

日期：2026-10-06。分支：`codex/steam-travel-game`。現有實作基準：`2d892cd`。

本次試玩後，核心方向由「排列合格行程後提交」轉為「回合制對話攻防，最後攤牌」。這份 handoff 記錄已明確提出的需求、討論中的建議，以及仍需定案的規則；不是新版施工規格，也不代表新機制已實作。

## 產品定位與文件優先序

- 網頁工具版在 `codex/web-travel-tool`，目標為真正可用、同時有趣的旅行規劃工具。
- Steam 版為旅行題材獨立遊戲，玩家沒有實際旅行需求也應願意重玩。
- 美術方向維持誇張職場喜劇、2D 漫畫角色與旅行社題材。
- 本次新需求優先於舊設計稿中衝突的玩法方向。舊文件仍記錄現版如何建成，不能直接當作新版施工依據。
- 舊規格：`docs/superpowers/specs/2026-10-06-steam-first-encounter-design.md`。
- 舊計畫：`docs/superpowers/plans/2026-10-06-steam-first-encounter.md`。

## 使用者試玩回饋

現版可在一輪排滿行程後成交，缺乏壓力推進、抽牌循環與策略攻防。使用者認為機制不成立；即使定位成教學，也缺少完整引導。

試玩中使用者詢問「交通？卡牌在哪？」及「所以我怎麼提交？」。當時手牌沒有交通卡，預設交通已自動套用，但介面沒有充分說明。這反映資訊與操作引導不足，不能只以規則能運作判定體驗完成。

## 已明確提出的新版需求

### 主要出牌是對話攻防

玩家在交鋒期間使用對話牌，對應《殺戮尖塔》的普攻、普防與技能。景點排入時間軸不再是戰鬥期間的主要動作。

《殺戮尖塔》作為回合與牌庫循環的參考；《逆轉裁判》作為角色交鋒、追問、資料查閱與關鍵反駁演出的參考。這些是設計參照，不是使用其角色、台詞、標誌或原始美術的授權。

### 每回合抽牌與交棒

不能用「起手六張＋兩次換牌」代替回合制抽牌。需要抽牌堆、手牌、棄牌堆與回合循環；特殊禁止抽牌等狀態須能被明確表達。

玩家結束行動後，輪到客戶說話施壓，造成精神傷害或其他效果。對話須是行動的演出，與實際結算連動，不能只是一段裝飾文字。

「無牌可出」包含手牌空、資源不足、無合法目標或受限制，也包含玩家判斷目前沒有合適的牌。最後一種可能仍有合法出牌，不能由程式以「存在可出牌」否定玩家結束回合的選擇。

### 行程可隨時點開，最後才正式攤牌

`YOUR ITINERARY` 不再常駐占據主畫面，改成可點擊開啟／關閉的「行程提案」區塊。

使用者後來明確補充：行程不是直到結尾才可以看，而是交鋒期間可查閱，最後再正式攤牌。不能把早先的「最後才出現」當成最終需求。

主畫面應聚焦角色、對話、客戶意圖與對話手牌。行程、需求與承諾屬於可查閱資料，不能再次把戰鬥畫面做成常駐行程管理表。

## 助理提出且待新版規格定案的設計

以下是建議，不應誤寫成使用者已逐項核准的規則或數值。

### 回合流程建議

客戶意圖可見 → 回合開始恢復行動力與抽牌 → 玩家出牌或查閱資料 → 玩家主動結束回合 → 客戶發話與攻擊結算 → 棄牌／清理與下一回合。

未使用手牌原則上進棄牌堆，保留牌例外；抽牌堆不足時洗入棄牌堆，消耗牌退出本場。抽牌、棄牌、護盾清除與敵方狀態觸發的精確順序仍需規格化。

保留明確「結束回合」按鈕。無合法牌可出時可醒目提示，但不應突然自動扣血；即使仍有合法手牌，也能主動結束回合。查閱資料建議不消耗行動力。

### 對話牌示例

| 牌型 | 台詞示例 | 設計作用 |
|---|---|---|
| 普攻：提出理由 | 這兩站順路，能少走不少冤枉路。 | 削減客戶疑慮 |
| 普防：接住情緒 | 我懂，你不想放個假還比上班累。 | 防護精神傷害 |
| 技能：追問需求 | 你最在意的是走太多，還是排隊？ | 抽牌或揭露弱點 |
| 承諾：安排專車 | 這段安排接送，不用自己走。 | 強力化解，但增加最終方案成本 |

這些牌名、效果與是否採用「疑慮」資源尚未定案。先前提出「削減疑慮至零進入攤牌」時，使用者沒有明確回答此勝利條件，因此不能當作已確認。

### 有內容的攻防

避免把普通傷害牌改名為話術就算完成。客戶正在質疑的內容應改變回應價值：質疑走路太多時，順路證據有額外效果；質疑預算時，相同理由沒有回答核心問題。

意圖與線索須讓玩家看得懂，不能讓玩家猜作者的唯一正解。基本攻防仍應有作用，不能讓一次抽不到對應牌就必敗。

承諾可換取眼前優勢，但把成本與義務留到最後攤牌。承諾與已知後果須隨時可查，不可結尾突然新增隱藏條件懲罰玩家。

### 下一個原型的建議範圍

建議先做一位客戶、約 4–6 回合、一次最後攤牌，驗證核心循環，再考慮爬塔、牌組成長及跨案件資源延續。4–6 回合是節奏目標，不是已定案的硬性回合上限。

教學建議採固定起手與事件，逐步引導看意圖、普攻／普防、結束回合、敵方傷害、下一回合抽牌與最後攤牌，再留一次無提示練習。正常遊戲再導入隨機牌序。

## 已被後續討論修正的方向

- 「實際帶團、逐時段推進」是助理先前提出的轉向，使用者後續指定交鋒期間用對話攻防。不要沿用帶團執行景點作為已核准核心。
- 「已執行景點退出本場、應變牌循環」是前述帶團方案下的建議，尚未確認適用新版對話戰。
- 「行程只在結尾可見」已被「隨時可點開、結尾正式攤牌」修正。
- 先前 8 點傷害、減傷 3、防護 4 等數字僅是解說例子，不是平衡參數。
- 舊版 6 張起手、2 次換牌、3 格精神與無成本自由重排，不能直接移植為新版戰鬥規則。

## 尚待決定

1. 玩家身份與場景：是否整場都在接待桌前談判；如何呈現對方回合及反駁。
2. 勝敗與攤牌觸發：削減疑慮至零、累積說服進度，或其他條件；精神歸零是否立即失敗。
3. 回合資源：起手／每回合抽幾張、行動力、牌費、護盾持續時間、抽牌禁止狀態、洗牌與棄牌順序。
4. 沒有合適手牌時的選擇：基本防守是否足夠，是否提供有限換牌，以及避免無法反應的規則。
5. 行程資料來源與編修：預設方案、由承諾自動修改，或攤牌時有限調整；查閱與修改要區分。
6. 承諾如何綁定效果與成本：專車、休息、餐廳等如何計入攤牌；可否撤銷、如何顯示可兌現性。
7. 攤牌結果：對話戰勝利是否仍可能因無法履約而破局，或只是影響評價；須事先向玩家說明。
8. 客戶意圖與對話標籤：如何讓回應有情境差異，又不變成只有單一正解的配對題。
9. 教學範圍、正常遭遇長度與後續成長路線。

## 現有程式狀態與可沿用部分

本 handoff 沒有改動遊戲程式。`2d892cd` 仍是舊版行程排列原型，不具有新的回合攻防系統。

| 路徑 | 現況與後續用途 |
|---|---|
| `src/data.js` | 景點／餐飲／休息／交通卡與虛構行程數值；新版對話牌需另行設計 |
| `src/rules.js` | 行程時間、預算、疲勞與可行性計算；可評估是否用於最後攤牌 |
| `src/deck.js` | 保證可解的六張起手與兩次換牌；需重做回合抽棄循環，不能只補抽牌按鈕 |
| `src/state.js` | 開場、安排、提交反應、結案；需改為玩家／客戶回合與攤牌狀態 |
| `src/dialogue.js` | 依方案問題生成回應；可沿用表情／台詞格式，內容與觸發邏輯需改 |
| `src/presentation.js` | 可取消打字、減少動態、音效與偏好；可沿用 |
| `src/view.js`、`styles/game.css` | 常駐行程表與景點手牌；需改為對話戰主畫面及可開關行程資料 |
| `src/main.js` | 事件串接、焦點及素材 fallback；可保留通用部分，重接戰鬥流程 |
| `assets/` | 原創旅行社背景、五種角色表情、十二張旅行卡圖、本機字體；旅行卡圖不是已完成的對話牌素材 |
| `tests/` | 30 項現版測試；新版須新增回合、攻防、抽棄、承諾與攤牌測試 |

上一輪驗證涵蓋 744 種可產生的起手組合與 23,762 個可用起手換牌選項。這只證明舊規則的可解性，不能證明新方向好玩。

## 瀏覽器與驗收狀態更新

早期 `file://` 預覽曾被工具拒絕。後來使用者已開啟 `http://127.0.0.1:8080/`，助理於交通卡問題時成功讀取該既有頁面的 DOM 與畫面，確認當時行程與三張剩餘手牌的位置。先前「完全無法查看遊戲」不再是當前狀態。

這次查看不等於完整的 1280 × 720／1920 × 1080、音效、離線與鍵盤驗收；`docs/steam-playtest.md` 為前次施工當時的紀錄。後續應以新的實際頁面與工具權限重新判斷，不繞過安全限制，也不要機械沿用過期的全面阻擋結論。

## 建議接手順序與成功標準

先沿本 handoff 釐清勝敗、回合與攤牌規則，形成新版規格與施工計畫。保留原創美術和可用的演出基礎，避免只改 UI 名詞就繼續擴充舊行程解謎。

原型的核心問題：

- 每回合是否有值得考慮的不同選擇？
- 客戶下一句話是否真的改變玩家的打法？
- 沒有合適牌時，是否仍能理解風險並主動交棒？
- 承諾是否同時提供眼前優勢與可預期的後續代價？
- 失敗後，玩家是否知道下次想換哪種策略？

「可玩性更好」目前是設計判斷，尚未經新版可玩原型驗證。本次授權是整理 handoff、commit 與 push，不是開始新版機制施工。
